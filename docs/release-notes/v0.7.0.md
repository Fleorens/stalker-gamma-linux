# v0.7.0 — A launcher that looks like one, a modlist that survives updates, and mods that fix themselves

This is the biggest release since the MVP: every task from the "Adoption"
review (T17–T22) is delivered, the GUI got a full visual identity, and a
security pass closed nine findings from a self-audit. None of it changes how
you start: `stalker-gamma-linux install` still does the same thing it always
did.

## Your modlist survives "Install / Update GAMMA"

GAMMA's own wiki says it plainly: every update resets your modlist, your mod
settings, and your load order, and tells you to back up first. We were
already doing half of that without realizing it — MO2 profiles were copied
before each update — but nothing restored anything, save games weren't
covered, and the backup folder grew forever.

```sh
stalker-gamma-linux backup           # profiles + save games + overwrite, on demand
stalker-gamma-linux backup --list    # what you can go back to (date, contents, size)
stalker-gamma-linux restore <id>      # put one back — the current state is saved first
```

Automatic backups rotate at five; one you take yourself never gets rotated
away. `restore` refuses while the prefix is busy (the T13 lock) and never
mutates in place — it builds the replacement next to the original and swaps
by rename.

The other half is that the loss doesn't happen in the first place: every
`update` now does a **three-way merge** of `modlist.txt`. Your disabled mods,
your load order and anything you added are replayed on top of the new
upstream list, and the report says exactly what got carried forward.
`update --no-merge` keeps the old behaviour. Three hard guarantees keep the
merge honest: a mod upstream removed is never resurrected, a mod you added is
reinserted next to its nearest surviving neighbour, and when the merge isn't
sure, it doesn't guess — it keeps upstream's list, keeps your backup, and
says so.

## When the game crashes, it names a suspect

`play` has detached from the terminal since v0.6.0, which meant nothing was
watching the game anymore once it launched — and the one diagnosis that
matters most, attributing a crash to a mod, was never attempted at all
(the official Windows launcher doesn't do it either).

```sh
stalker-gamma-linux postmortem   # after closing the game: what happened, and which mod to suspect
```

It reads three logs — launch, X-Ray engine, USVFS — in the order failures
actually occur (launch failure > out of memory > engine crash > dead USVFS >
normal session), and turns the resource named in an engine crash trace into
the mod most likely to own it. It's a **suspect**, not a verdict: the actual
fault can be a neighbour in the load order, and the wording says so. A "Did
the game crash?" button appears on the main GUI screen right after a `play`.
Full analysis, attribution included, in ~20ms over 761 mods — the engine log
is never read in full, only its head and a `seek`-reached tail.

## GAMMA in your Steam library, artwork included

```sh
stalker-gamma-linux steam-shortcut            # add GAMMA to the Steam library
stalker-gamma-linux steam-shortcut --remove   # take it back out
```

This is the Deck/Bazzite/SteamOS answer to a limitation left open in v0.2.0:
*Add a Non-Steam Game* requires Desktop Mode, which doesn't exist in Gaming
Mode — exactly where the need is highest. `steam-shortcut` writes
`shortcuts.vdf` directly: our own binary VDF codec, validated with a
byte-for-byte round-trip against a real file. It refuses to write while
Steam is running (it would overwrite the file on exit, silently), keeps a
timestamped backup, and leaves everyone else's shortcuts untouched field by
field. Three capsule images, a hero banner, a logo and an icon are generated
entirely offline by our own procedural artwork — no SteamGridDB, nothing
downloaded. `install --steam-shortcut` does it at the end of an install.

## MangoHud, vkBasalt, and a layer that had to be removed

```sh
stalker-gamma-linux play --mangohud                 # FPS/frametime overlay
stalker-gamma-linux play --mangohud-preset full      # + CPU/GPU/VRAM, temperatures
stalker-gamma-linux play --vkbasalt                  # our "ReShade-like" preset (CAS + a generated LUT)
```

The README had promised a vkBasalt-based answer to the ReShade this installer
removes (incompatible with DXVK) since v0.1.0, with no code behind it. Both
layers are **off by default** — they change how the game renders, and
"nothing enabled" needs to stay a sentence a player can write without
checking. `doctor` lists both with the install command for your distro, and
now checks the actual **ELF class** of the layer library, not just its
manifest: a Fedora machine with only the 32-bit vkBasalt package installed
used to show `[ OK ]` while the 64-bit game silently never loaded it — the
worst failure mode a cosmetic setting can have.

A gamescope/FSR layer shipped alongside them and was **removed the same day**
it was measured against a real session: nested under a desktop Wayland
compositor (KDE/KWin here), it hits a Wayland protocol error and takes the
whole game down with it, mid-session, without warning. This is a known class
of bug upstream, and it doesn't happen on the Steam Deck, where gamescope
*is* the session rather than a nested client — precisely the case where FSR
matters most. Without a Deck to verify that nominal case, shipping a switch
that kills the only run we could test was worse than not shipping it. This is
a **breaking change** for anyone using the six `play --gamescope*` flags —
gone with the layer, along with `environment/gamescope.py`. The measurement
and the conditions for bringing it back are in `docs/ARCHITECTURE.md`.

## Shader cache that survives a repair

```sh
stalker-gamma-linux prefix-doctor --purge-shaders   # force a full recompile, or reclaim disk space
```

`install --only prefix` — the official remedy for "prefix has an invalid
version" — used to silently throw away hours of DXVK/driver shader
compilation along with the rest of the prefix. The shader cache now lives
under `<root>/cache/shaders/`, outside the Proton prefix, so `--only prefix`,
`prefix-doctor --repair` and a Proton-GE version change no longer touch it.
Measured for real: cold cache to warm, zero bytes recompiled for the same
rendered content.

## ModDB failures that explain themselves, and heal

```sh
stalker-gamma-linux install --retry-failed   # retry only the mods a previous install recorded as failed
```

ModDB occasionally blocks a download — a Cloudflare captcha, a dead link, a
corrupted archive — and it used to surface as a raw traceback. A single
marker table now classifies a download failure into one of three causes
(network/ModDB unreachable, broken link — drop the file yourself into
`<gamma>/downloads`, or a corrupted local archive — removed automatically),
names the mod involved, and remembers it. `--retry-failed` replays only those
mods, reusing the same repair mechanism `verify --repair` already uses.
No captcha bypass, no browser simulation: that stays out of scope.

## The GUI actually looks like a launcher

The previous look was a 200-line stylesheet in a Python f-string and a
background that amounted to a green haze over a gradient. It was clean, but
it didn't read as STALKER or as a launcher, and told you almost nothing at a
glance.

- The **background artwork** is redrawn in depth — the Duga antenna, the
  power plant chimney, dead pylons, distant forest, ground haze, a visible
  anomaly — then colour-graded (bloom, a two-tone shift, chromatic
  aberration, vignette, grain). Still fully procedural and deterministic, no
  external assets.
- The home screen gained a **bottom dock**, separated from the artwork by a
  glowing divider: identity, install path, three status tiles (free space,
  mods deployed, version), facing the actions. The mods tile now reads
  **"579 / 728"** — active in the GAMMA profile over installed — instead of
  one number that didn't match what MO2 itself reports.
- The progress screen gained a header bar with step/percentage/elapsed
  time/progress bar together, and a milestone timeline on a rail.
- The install dialog's disk-space gauge is now colour-coded by verdict,
  instead of making you subtract "143 GiB free" from "160 GiB required"
  yourself.
- The stylesheet is a real CSS file now (`gui/theme/style.css`), and the
  background artwork is decoded once for the whole application instead of
  once per page (9.6ms once, 3µs on reuse afterwards).

Two bugs were found and fixed while looking at the screenshots this
redesign generates: the progress console could render empty while its buffer
was full, and the stylesheet was producing a GTK warning on every redraw.

## A security hardening pass

A self-audit against OWASP/CWE found nine issues, all fixed in this release:

- an install path with a control character could inject into `.desktop`/ini
  files — now rejected;
- `libunrar` versions vulnerable to CVE-2022-30333 are now detected and
  flagged;
- the umu-launcher fallback archive is now verified by SHA-256 before use;
- `setuid`/`setgid` bits are neutralized on tar extraction on interpreters
  without `data_filter`;
- `read_remote_bytes` is now capped (CWE-400 — unbounded memory read from a
  remote response);
- `doctor --report` now anonymizes the account name and `/run/user/<uid>`,
  not just the home directory;
- GitHub Actions are pinned by commit SHA instead of a mutable tag, and the
  gitleaks binary's checksum is verified before it runs;
- `gamma-launcher` is pinned to a commit (not a tag) and the dependency
  closure is frozen in `constraints.txt`, audited weekly by a non-blocking
  `pip-audit` CI job;
- `install.sh` no longer treats an unrelated file as its own local checkout
  when `install.sh` happens to be a directory at the cwd.

## Also

- **Performance**: the GUI's progress screen now has a per-tick render
  budget and a bounded console (it could grow without limit on a long
  install); the integrity scan's MD5 hashing and `doctor`'s eight checks are
  now parallelized; a file whose size and mtime match the reference is no
  longer rehashed; the update-check safety net's requests are parallelized
  too.
- `doctor` no longer treats Proton Experimental as usable for a repair, and
  accepts GE-Proton directories with an `-x86_64` suffix.
- A missing `gi` import now names the interpreter that failed to find it.
- 22 empty or fuzzy strings in the French catalogue are translated.
- CI dependencies (`actions/checkout`, `setup-python`, `cache`,
  `upload-artifact`, `download-artifact`) are bumped to their latest majors,
  now kept current automatically by Dependabot.
- `docs/CI.md` and `docs/ROADMAP.md` were updated to match what's actually
  shipped and what `ci.yml` actually runs — both had drifted behind several
  merged tasks.

## Upgrading

```sh
curl -fsSL https://raw.githubusercontent.com/Fleorens/stalker-gamma-linux/main/install.sh | bash
```

or `./install.sh --no-launch` from an existing checkout. Your game, mods and
saves are untouched. If you use the `play --gamescope*` flags, they're gone —
see "MangoHud, vkBasalt, and a layer that had to be removed" above.
